## Keyboard model

| Key                     | Action                                               |
| ----------------------- | ---------------------------------------------------- |
| `ArrowUp` / `ArrowDown` | Move highlight (wraps at ends, skips disabled items) |
| `Home` / `End`          | Snap to first / last enabled item                    |
| `Enter`                 | Execute the highlighted item's `onSelect`            |
| `Escape`                | Close the palette (or pop a nested page)             |
| `Backspace`             | Pop the current page when the query is empty         |

## Nested pages

Items can push a new page via `onSelect`. Consumers hold the page stack
in controlled state — the palette resets query and highlight on push
and pop.

```tsx
const [pageStack, setPageStack] = useState<readonly string[]>([]);

<Command.Root pageStack={pageStack} onPageStackChange={setPageStack}>
  <Command.Dialog aria-label="Palette">
    <Command.Input />
    <Command.List>
      <Command.Group id="root">
        <Command.Item id="theme-menu" onSelect={() => setPageStack(["theme"])}>
          Change theme…
        </Command.Item>
      </Command.Group>
      <Command.Group id="theme-page" pageId="theme">
        <Command.Item id="light" onSelect={setLightTheme}>
          Light
        </Command.Item>
        <Command.Item id="dark" onSelect={setDarkTheme}>
          Dark
        </Command.Item>
      </Command.Group>
    </Command.List>
  </Command.Dialog>
</Command.Root>;
```

## Global keyboard shortcut

`useCommandShortcut` attaches a `keydown` listener without registering a
global command registry — it wires a single shortcut to a single
`onTrigger`.

```tsx
useCommandShortcut({
  key: "k", // Ctrl/Cmd + K by default
  onTrigger: (event) => {
    event.preventDefault();
    setOpen(true);
  },
});
```

## Filtering

The default filter is a case-insensitive word-boundary substring match
across each item's `searchText` (auto-derived from rendered content) and
`keywords`. Consumers who need fuzzy search supply a custom `filter`
prop — no fuzzy search dependency is bundled by default.

```tsx
import { fuzzyMatch } from "your-fuzzy-lib";

<Command.Root filter={(item, query) => fuzzyMatch(item.searchText, query)}>{/* … */}</Command.Root>;
```

## Consumer-provided execution

Command never persists on its own. Each item's
`onSelect` is the only place execution happens. String-driven or
arbitrary code evaluation is out of scope.

<Callout type="warning" title="Not shipped">
  - Global command registry — deferred; each palette owns its items. - Fuzzy-search dependency —
  opt-in only. - Arbitrary code execution via strings — not supported. - Application commands baked
  into the library — consumers own them.
</Callout>

## Controlled state

Every stateful concern is controllable. Pair the controlled value with
its `on*Change` callback and the palette never writes internal state:

- `open` + `onOpenChange`
- `query` + `onQueryChange`
- `highlightedId` + `onHighlightChange`
- `pageStack` + `onPageStackChange`

Omit the controlled value to let the palette own that slice; both modes
compose freely.

## Performance guidance

- Items register themselves lazily — the registry rebuilds only when
  the mounted item set changes. Hiding filtered items via the `hidden`
  attribute keeps DOM refs stable and avoids re-renders.
- For catalogues above a few hundred items, pre-filter in a derived
  memo before mounting `Command.Item` elements. The palette does not
  ship list virtualization in v1.
- The default filter walks the registered item list once per query
  keystroke; the complexity is linear in the mounted item count.

## Package boundary

`Command` ships only in `@kairoui-pro/command`. Overlay primitives
(`Portal`, `FocusScope`, `DismissableLayer`) are consumed from
`@kairoui/core` — nothing is duplicated. Free consumers who want a
plain-overlay palette can compose those primitives directly without the
Pro surface.

## API and DX gaps

- Large command sets still require consumer pre-filtering or paging;
  list virtualization is not built into v1.
- The generated API table cannot encode structural usage rules (for
  example, that actionable items must be children of `Command.List`).
- Alias exports such as `CommandItemComponent` are intentionally
  low-level and are not primary docs entry points.
