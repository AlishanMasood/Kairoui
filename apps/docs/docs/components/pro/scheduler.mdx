## Anatomy

```tsx
<Scheduler
  events={events}
  resources={[{ id: "r1", label: "Room A" }]}
  defaultView="week"
  defaultDate={new Date()}
  onEventClick={({ event }) => open(event.id)}
  onMoveEvent={({ event, start, end }) => reschedule(event.id, start, end)}
  onResizeEvent={({ event, start, end }) => reschedule(event.id, start, end)}
  onCreateRange={({ start, end }) => createDraft(start, end)}
/>
```

For custom layouts, pass compound children explicitly:

```tsx
<Scheduler events={events}>
  <Scheduler.Toolbar />
  <Scheduler.Views>
    <Scheduler.WeekView />
  </Scheduler.Views>
  <Scheduler.EventTemplate
    render={({ event, isSelected }) => <MyEventCard event={event} highlighted={isSelected} />}
  />
</Scheduler>
```

## Data model

```ts
interface SchedulerEvent {
  id: string;
  start: Date;
  end: Date; // exclusive
  allDay: boolean;
  resourceId?: string;
  title: string;
  description?: string;
  meta?: Record<string, unknown>;
}
```

`end` is **exclusive** — an event `09:00 → 10:00` does not overlap
`10:00 → 11:00`. Timestamps are **local wall-clock** `Date` objects;
the Scheduler never converts timezones.

<Callout type="warning" title="Timezone policy">
  The Scheduler renders entirely in the browser's local wall-clock. Consumers who store events in a
  specific zone must convert to a local `Date` before passing them and convert back inside
  `onMoveEvent` / `onResizeEvent` / `onCreateRange`. `timezoneLabel` is a **display-only** hint —
  changing it does not shift layout.
</Callout>

## Keyboard model

| Key                                 | Action                                    |
| ----------------------------------- | ----------------------------------------- |
| `ArrowUp` / `ArrowDown`             | Move focused event by one slot            |
| `Shift+ArrowUp` / `Shift+ArrowDown` | Resize end by one slot                    |
| `Ctrl+ArrowUp` / `Ctrl+ArrowDown`   | Resize start by one slot                  |
| `Alt+ArrowLeft` / `Alt+ArrowRight`  | Move focused event to previous / next day |
| `Enter` / `F2` / `Space`            | Fire `onEventClick`                       |
| `Escape`                            | Cancel drag or clear selection            |
| `PageUp` / `PageDown`               | Navigate previous / next view period      |
| `Home`                              | Jump to today                             |

The keymap is data-driven — override any binding via the
`DEFAULT_SCHEDULER_KEYMAP` export.

## Callbacks

| Callback          | Payload                                         |
| ----------------- | ----------------------------------------------- |
| `onEventClick`    | `{ event, nativeEvent }`                        |
| `onCreateRange`   | `{ start, end, resourceId?, allDay }`           |
| `onMoveEvent`     | `{ event, start, end, resourceId? }`            |
| `onResizeEvent`   | `{ event, start, end, edge: 'start' \| 'end' }` |
| `onOverflowClick` | `readonly SchedulerEvent[]`                     |
| `onViewChange`    | `SchedulerViewKind`                             |
| `onDateChange`    | `Date`                                          |

The Scheduler never persists changes — the consumer applies each
payload to their own store, and the new event data flows back through
the `events` prop.

## Accessibility

- Root exposes `role="application"` with
  `aria-roledescription="Scheduler"`.
- The time grid uses `role="grid"` with `aria-rowcount` /
  `aria-colcount`.
- Every event is a focusable `role="button"` with
  `aria-label` and `aria-pressed`.
- A single `aria-live="polite"` region announces view changes.
- All bindings honor `prefers-reduced-motion`.

## Locale and RTL

- `locale` — BCP 47 tag consumed by `Intl.DateTimeFormat` for hour and
  day-of-week labels.
- `weekStartsOn` — 0 = Sunday, 1 = Monday, …; derived from the locale
  when omitted (falls back to Monday).
- `hour12` — 12-hour / 24-hour toggle; derived from the locale when
  omitted.
- `dir="rtl"` — flips visual flow. Timeline time direction stays LTR
  by default to match Gantt-style conventions.

## Non-goals for v1

- No recurring-event engine — consumers expand recurrences before
  passing.
- No timezone conversion — the escape hatch is explicit, never
  automatic.
- No conflict / availability blocking.
- No month or agenda view (deferred).

## Controlled state

The toolbar / view / selection / drag triples are all controllable.
Pair the controlled value with its `on*Change` callback:

- `view` + `onViewChange`
- `date` + `onDateChange`
- `selection` + `onSelectionChange`

Drag and resize are **callback-only** — the Scheduler never writes to
your event store. `onMoveEvent`, `onResizeEvent`, and `onCreateRange`
hand you plain-data payloads with pre-snapped `start` / `end`; apply
them to your own store and the new data flows back through the
`events` prop.

## Performance guidance

- Events outside the current view are filtered before layout runs, so
  loading a month at a time is cheap. For year-view loads, chunk by
  week before passing.
- `minRenderedMinutes` controls the lower bound on event height so very
  short events (sub-15-minute slots) stay clickable without widening
  the slot grid.
- `maxEventsPerSlot` caps per-cell concurrency; events beyond the cap
  spill into an "overflow" chip that fires `onOverflowClick`.
- Timeline view is horizontal — resource rows virtualize naturally
  through CSS scroll; the number of resources is not an upper bound.
- The scheduler never clones `Date` objects on the hot path. Pass
  frozen or memoized events to avoid cascading re-renders.

## Backend independence

The Scheduler ships zero backend adapters.

- Events are plain data — fetch them with any library, store them in
  any state container, and persist them to any backend. The Scheduler
  only reads the `events` prop and emits plain-data callback payloads.
- Timezones are **not** converted. The ADR is explicit: all `Date`
  values are rendered in local wall-clock. Consumers wrapping an
  IANA-aware backend must convert at the boundary.
- Recurrence is not resolved. If your backend stores an RRULE, expand
  it in a derived memo before passing to the `events` prop.

## Package boundary

`Scheduler` ships only in `@kairoui-pro/scheduler`. There is no free
Scheduler component — the free tier does not include a calendar grid
primitive (see [`Calendar`](/components/core/calendar) for the day
picker surface). The Pro package re-uses `@kairoui/core` overlay and
`@kairoui/hooks` focus utilities; nothing is duplicated.

## API and DX gaps

- Timezone behavior is explicit but manual: consumers must convert at
  IO boundaries for non-local storage models.
- Recurrence expansion is consumer-owned. The scheduler accepts concrete
  instances only.
- Selection types are expressive but verbose, which can feel heavy in
  app-level state wiring.
